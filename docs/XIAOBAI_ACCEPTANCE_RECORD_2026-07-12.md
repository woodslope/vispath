# AI 视觉方向画板体验验收记录

## 1. 产品与任务

- 产品 / 页面：AI 视觉方向画板
- 页面类型：本地优先的单页工作台
- 目标用户：需要比较多个视觉提示词方向的内容创作者和设计人员
- 核心任务：输入原始提示词，生成方向方案，选择方案并提交到右侧生成画板
- 运行模式：本地模拟数据；生成历史保存在浏览器 IndexedDB；不调用真实 API
- 验收日期：2026-07-12

## 2. 验收结论

- 用户体验结论：**建议修改**
- 工程运行结论：**未执行**；本次仅做用户体验验收
- 未覆盖项：真实 API 的限流、超时和服务端故障；第二种真实页面类型；真实用户任务测试

## 3. 通用三步

### 任务可发现

- 页面名称、三栏顺序和本地原型边界清楚，用户能理解“左侧建立探索 -> 中间选择方案 -> 右侧查看生成记录”。
- 初始空状态能说明输入条件和后续结果位置。
- `1280x768` 下“生成视觉方向”按钮位于页面纵向约 `1261-1299px`，不在首屏，需要滚动左栏后才能发现。这会增加首次使用者判断下一步的成本。
- 证据：真实浏览器 DOM、元素位置和主路径操作。

### 状态可理解

| 状态 | 适用性 | 是否检查 | 结果与证据 |
| --- | --- | --- | --- |
| 首次 / 空状态 | 适用 | 是 | 三栏均有明确空状态和下一步说明 |
| 可操作 | 适用 | 是 | 输入提示词后可执行生成；方案生成后可选择并提交 |
| 处理中 | 适用 | 是 | 按钮显示“正在梳理提示词…”，同时禁用；提交后出现生成中卡片 |
| 成功 | 适用 | 是 | 生成 3 套提示词；提交 1 套后出现 1 张完成卡片 |
| 失败 | 适用 | 是（本地模拟） | 提示词包含“模拟失败”时，生成卡显示失败状态和具体原因 |
| 恢复 / 重试 | 适用 | 是（本地模拟） | 点击失败卡的“重试”后进入处理中并恢复为已完成；刷新后仍保留恢复结果 |
| 返回 / 恢复数据 | 适用 | 是 | 刷新后 1 条完成记录仍存在 |
| 边界 / 退出 | 适用 | 是 | 空输入提示“先输入提示词或上传参考图”，并聚焦原始提示词输入框；重置会立即清空输入、方案和历史 |

### 完成成本可接受

- 桌面端：三栏职责清楚，主操作已固定在左栏底部的可见操作区。
- 移动端：布局正确变为单列；用户需依次跨过建立探索、提示词方案和生成画板三个长区域，完成一次任务的纵向移动较多。
- 页面 / 模块跳转：无页面跳转，全部在单页内完成。
- 重复输入或上下文记忆：无需重复输入；提示词快照和历史记录会保留。
- 结论：主路径可完成，桌面首屏可发现性问题已修复；移动端纵向成本仍需优化。

## 4. 响应式与运行证据

| 视口 / 环境 | 是否检查 | 横向溢出 | 关键操作可达 | 控制台错误 | 备注 |
| --- | --- | --- | --- | --- | --- |
| `1280x768` | 是 | 无 | 可达，操作区约位于 `684-759px` | 无应用错误 | 三栏约为 `290 / 320 / 604px` |
| `390x844` | 是 | 无 | 可达，主路径已实际走通 | 无应用错误 | 工作区单列，生成画板瀑布流单列 |

主路径证据：

1. 输入咖啡店海报提示词，点击“生成视觉方向”。
2. 处理中按钮禁用，随后生成 3 套提示词方案。
3. 选择 1 套并提交，右侧先显示生成中，再显示 1 张完成卡片。
4. 刷新页面，完成卡片仍能恢复。
5. 在 `390x844` 下重复生成和提交，生成记录由 1 条增加到 2 条。
6. 重置后输入、提示词方案和 2 条历史记录全部清空；空输入操作会提示并聚焦输入框。

## 5. 问题与优先级

| 优先级 | 问题 | 违反的验收层 | 影响 | 建议动作 |
| --- | --- | --- | --- | --- |
| P1 | 真实 API 的部分错误类型尚未验证 | 状态 | 成功链路与本地失败重试已覆盖，但未主动消耗额度制造限流、超时或服务端故障 | 在真实错误发生时记录并回归对应状态 |
| P2 | 移动端主路径纵向距离较长 | 成本 / 响应式 | 频繁上下滚动，结果与输入相距较远 | 增加阶段导航或移动端紧凑布局，并保留当前上下文 |
| P2 | 重置立即清空全部历史，且不可恢复 | 边界 | 误触会造成不可逆的本地记录丢失 | 增加二次确认，或提供短时撤销 |
| P2 | 模拟图片边界仍可更明确 | 边界 | 用户可能把完成卡片误认为真实生图结果 | 在生成画板空态和结果卡中持续标注模拟状态 |

## 7. 后续复测（2026-07-12）

- 已修复：桌面左栏主操作改为底部 sticky 操作区。
- 复测结果：`1280x768` 下按钮位于可见操作区约 `684-759px`，无横向溢出；`390x844` 下操作区恢复普通流式布局，主路径仍可完成。
- 已补齐：本地模拟失败、错误原因、单卡重试、恢复成功及刷新持久化闭环。
- 已接入：兼容 OpenAI Images 接口的真实图片生成服务；验证了代理请求、真实图片返回、本地落盘和通用前端图片 URL 契约。
- 已接入：兼容 OpenAI Chat Completions 接口的真实文本方案服务；使用严格 JSON Schema 返回 PromptBlueprint，并验证 2 套方案在页面中正常渲染。
- 已接入：参考图多模态解析；验证了无文字、仅参考图输入时可返回 2 套方案，并在 Blueprint 中记录参考图来源。
- 已自动化：Playwright 定向体验测试可注入内存图片，并验证文件选择、客户端压缩预览、限流 / 服务故障 / 超时反馈、移动端阶段状态、单条历史删除、撤销及刷新后的持久化结果。
- 已迁移：生成历史升级为 schema v2；读取和保存均使用字段白名单，旧 `provider`、`model`、`shouldFail` 字段会自动移除，图片 URL、状态、提示词和批次继续保留。
- 已优化：`390x844` 下新增“输入 / 方案 / 结果”固定阶段导航；初始仅开放输入，生成方案后自动解锁方案，点击后目标区停在导航下方且无横向溢出。桌面 `1280x768` 仍保持三栏布局且不显示移动导航。
- 已优化：移动端阶段导航会随点击和滚动标记当前所在阶段；生成历史支持单条删除，并立即同步 IndexedDB。
- 已优化：单条删除提供 5 秒撤销入口；历史写入按快照串行执行，避免删除与撤销连续操作时发生覆盖竞争。
- 已优化：移动端压缩表单间距和无内容区域高度，保留全部核心控件与阶段跳转。
- 已清理：单条删除在撤销窗口结束后清理对应 `generated/` 图片；待清理任务可在刷新后恢复，重置成功后立即清理剩余图片。删除接口只接受项目内安全文件名并保持幂等。
- 已优化：移动端提示词蓝图默认折叠，可通过 `40×40px` 展开按钮查看；桌面端始终展开。
- 视觉复核修正：左侧主操作栏改为表单流内的普通底部区域，移除与“本轮探索什么”内容的固定定位重叠；桌面端需在左侧面板内滚动到表单末尾执行主操作。
- 已清理：移除前端不再调用的本地 Mock Blueprint 构建代码，提示词方案统一由已连接的文本服务生成。
- 已修复：重置增加二次确认；默认焦点位于“取消”，取消后输入保持不变，确认后才清空输入、方案和历史。`390x844` 下对话框无溢出，按钮尺寸为 `306x44px`。
- 已通用化：API 配置对外提供“文本与生图共用”和“文本与生图独立”两种方式；底层继续兼容专用配置覆盖共用配置。前端只显示文本 / 生图能力状态，不显示配置地址、密钥、供应商或模型。
- 当前仍保留的问题：真实 API 的限流 / 超时 / 服务端故障验证、移动端纵向成本和重置不可撤销。
